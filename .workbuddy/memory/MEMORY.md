# 项目长期约定（图书编辑实用技术）

## 项目定位
基于作者 2018 年以来的编辑技术博客（源库 `D:\Users\ah21\OneDrive\ah21\blog\docs\`，只读）继续写作。工作区为本目录。

## 产出形态（作者 2026-10-18 确认）
- **写作单位是"片段"**：每次写一个小技术点，几百字，来自当天真实书稿工作；正则类可每天一两条。
- **片段不单独发表**，唯一出口是归集后的文章；只有整合完成的文章才发布。
- 片段四段结构：场景 / 做法 / 说明 / 边界；文件头标 主题、归集到、日期、适用版本、状态。
- **片段去留由作者定**：默认存 `片段/`（状态"待归集"）；作者明确说"并入某篇"才插入该文合适位置并更新 Modified；没有命令不得改动任何既有文章。可建议并入位置，但必须等命令。
- 目录：`片段/<主题>/日期-动作短语.md`；发表稿放 `归集/`，`归集/_模板.md` 为模板。
- 合并对象是 `过往文章/` 的副本，博客源库只读；副本定稿后由作者回写（或经同意代写）。

## 发表稿格式（照博客现有文章）
- 文件名 `YYYY-MM-DD-标题.md`。
- YAML front matter 字段与顺序：title / Slug / Category / tags / Authors / Date / Modified / Status / Summary；Slug、Category、Summary 常留空，tags 二级列表 2～3 个，Authors 填作者名，Modified 随实质修改更新。
- 正文不写"系列第 N 篇""前文提到过"等跨篇指代。

## 读者定位
- 以**一般图书编辑**为主，其他文字工作者（作者、编校外包等）为辅；教育出版编辑的"编研一体"需求属细分照顾，非默认画像。
- 初始环境：Windows + Word / WPS。
- 推广目标：① 最流行的文本编辑器，重点 VS Code，兼及 EmEditor、TextPro；② LibreOffice，作 Word/WPS 的替代品。
- 全程判断标准：读者能不能当天照着做出来。

## 选题标准
收：编辑器与办公软件（Word/WPS/LibreOffice/EmEditor/TextPro/VS Code）、正则与批量处理、效率工具、实用排版（简单标记类 ConTeXt/Typst）、AI 辅助编校、出版规范、相关行业知识。
不收：需编程才能用（除非包装成装好即用的成品工具）、排版底层技术（TeX 内部机制、Lua 回调、结点列表）、与图书编辑无关的主题。
判断"标记 vs 编程"：是否需要理解变量、函数、控制流。

## 协作分工
观点与经验由作者出，查证与成段辅助由智能体出；不得替作者编造经验；发现判断有误先讨论不擅改。
