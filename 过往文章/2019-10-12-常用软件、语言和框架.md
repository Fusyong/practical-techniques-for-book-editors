## 老编辑必备

### 文本处理

* 正则表达式，大多数文本编辑器都支持
    * 文档分行，以便git管理：`[。！？：;][”）]*`替换为`$0\n`
* VS Code，最受欢迎的文本编辑器，支持各种语言、丰富的插件、Git版本控制、快捷方式等，社区巨大并且活跃
* TextPro，有一些针对汉字、拼音的正则处理功能，支持批量正则替换
* EmEditor，快速启动、处理大文件，跨行正则处理，表格模式
* LibreOffice Writer，正则处理MS Word文档，命令行批处理。使用问题参见[libreoffice使用问题](2021-09-01-libreoffice使用问题.md)


### AI校对、修改稿件

* 中文稿件用 Deepseek V3、Gemini 2.0、Claude 3.5等大模型处理。一般书稿处理建议：
    1. 转换成markdown文件
        1. docx文件可用 pandoc 转换成markdown/markdown_strict，再手动处理个别转义内容（以`\`开头）、表格、图像链接等
        2. PDF文件(有完善格式标签的更好)，先剪去页眉页脚等影响文本流的内容，再通过Acrobat/Parsr/pdf2htmlEX转换成HTML，再用pandoc转换成markdown，再手动清理；如果不需要保留太多格式，可以直接转换成markdown或text
    2. 用脚本程序分成长度适宜（比如六百到八百字符）的小块，再调用API处理
    3. 还可以尝试进行多次专项校对（比如专名审校，一次要处理一个完整的章节）
    4. 用vscode、Word、jsdif、Python库difflib等比较修改前后的文本，将有价值的修改誊抄到书稿上（如果熟悉技术流程，并且保证书稿后续还会经过人工审校，那么也可以直接在比较界面处理）
* 英文稿件用Grammarly、QuillBot、Google Doc等提供的拼写与语法检查服务处理；或通过vscode使用Harper语言服务器（目前只支持美语），效率更高，但没有AI支持

### 音视频转换：FFmpeg

* 截取视频

```bash
# -ss 始时； -i 输入源； -t 到时； -c:v 视频编码； -c:a 音频编码
ffmpeg -ss 00:00 -i original.mp4 -t 00:62 -c:v copy -c:a copy output.mp4
```

* 图像序列转为视频：

```bash
ffmpeg -f image2 -r 24 -i img%03d.jpg -c:v libx264 -pix_fmt yuv420p out.mp4
# -f输入文件类型；
# -r 帧率，在-i前为输入帧率，在输出前为输入帧率；
# %03d表示三位数字序列；
# 多行命令各新开窗口并最小化依次等候处理：每行前加`start /wait /min`，后加回车空行
```

* 拼接文件

[详见](https://trac.ffmpeg.org/wiki/Concatenate)

```bash
ffmpeg -i "concat:1.mp3|2.mp3" -c copy output.mp3
```

或预先做成文件列表mylist.txt

```bash
# this is a comment
file '/path/to/file1'
file '/path/to/file2'
file '/path/to/file3'
```

然后：

```bash
ffmpeg -f concat -safe 0 -i mylist.txt -c copy output
```

如果是相对路径，不需要`-safe 0`


如果wav录音文件使用`ffmpeg -i input1.wav -i input2.wav -acodec output.wav`   `命令拼接的录音最终输出的录音只有第一段。
原因是wav的音频编码格式不属于MPEG 类，所以需要加一个过滤器。解决办法：
```bash
ffmpeg -i input1.wav -i input2.wav -filter_complex '[0:0][1:0]concat=n=2:v=0:a=1[out]' -map '[out]' output.wav
```
根据录音数量需要修改的就只是[0:0][0:1]和n=2 这两个的数量。比如三个文件拼接就用：
```bash
ffmpeg -i input1.wav -i input2.wav -i input3.wav -filter_complex '[0:0][1:0][2:0]concat=n=3:v=0:a=1[out]' -map '[out]' output.wav
```


### 文档转换

#### Pandoc

[demo](https://pandoc.org/demos.html)

markdown转docx：

```shell
pandoc -o output.docx -f markdown -t docx filename.md
```

[docx转markdown，含图：](https://gist.github.com/plembo/409a8d7b1bae66622dbcd26337bbb185#file-pandocdocx2md-md)

转换markdown，省略号、破折号、引号等会出错，可以加`-smart`，禁用智能标点转换。如设置：

```bash
set myfilename="myfilename"
pandoc -f docx -t markdown-smart+pipe_tables+footnotes --wrap=none --toc --extract-media="./attachments/%myfilename%" %myfilename%.docx -o %myfilename%.md
```

也可以再转一个markdown_strict来核对。（[各种变体](https://pandoc.org/MANUAL.html#markdown-variants)）

```shell
set myfilename="myfilename"
pandoc -t markdown_strict --extract-media="./attachments/%myfilename%" %myfilename%.docx -o %myfilename%.md
```

用MS Word批量转换工具转换当前路径下所有doc为docx：

```shell
for /R %f in (*.doc) do "C:\Program Files (x86)\Microsoft Office\root\Office16\Wordconv.exe" -oice -nme "%f" "%fx"
```

docx转ConTeXt:

```shell
pandoc -t context -f docx -o b.tex "a.docx"
```

转换后，后点引号、破折会、全角连接号、部分省略号有出错或转换，可以再转一个markdown_strict来核对。

* [py5](https://py5coding.org/), 通过语言桥JPype，把Java Processing jars暴露给CPython解释器，整合到Python生态中，可与Jupyter、numpy、shapely、trimesh、matplotlib、Pillow等常用库一起使用。需要安装JDK 17 以上，并正确配置系统环境变量"JAVA_HOME"。另有Thonny编辑器插件，但自动完成似乎有问题。

    * 帧率略差
    * 部分接口可以手动转写成p5.js代码，在线展示
* [pyp5js](https://github.com/berinhard/pyp5js)，从Python到P5.js的转写器（**因此无法通过编辑器获得代码编写辅助**）

    * API与p5.js高度兼容
    * 用Transcrypt转写帧率更高，但支持的库有限，适合Python入门
    * 用pyodide运行在WASM中则文件较大（官方库可离线），帧率低，但支持很多科学库

* 符号链接(symbolic link，依赖链接对象)
    * 文件 `mklink linkname.txt target.txt`
    * 目录（路径/文件夹）`mklink /D d:\develop \\138.20.1.141\e$\develop`

* 文件的硬链接(hard link，不依赖链接对象，数据别名)`mklink /H linkname.txt target.txt`
